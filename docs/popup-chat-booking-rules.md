# TEST: chat, lead-form, and booking-popup timing

The Living in Raleigh timed lead popup never opens while the custom chat is open. If a popup is already open when chat starts, it closes. Closing an unused chat restarts the original 10-second timer; closing after sending a message defers the popup for 30 minutes. That quiet period survives a page reload in the same browser session. A completed contact request in chat counts as a form submission and uses the form-follow-up rule instead.

After a Living in Raleigh form's browser request completes, the site records a local lead-captured flag and schedules a booking-only follow-up two minutes later. The popup opens directly to its calendar screen, not to the already-completed lead form. The follow-up is shown at most once on that browser. The website popup form also follows this rule after its thank-you screen is closed. The covered forms are the timed lead popup, call-me form, home-valuation form, new-construction form, neighborhood-fit quiz, suburb quiz, and chat contact handoff. Because the existing Google Apps Script transport uses `no-cors`, browser completion alone does not prove the backend accepted a lead row.

The button **I received my booking confirmation** in the popup and on `/consult/` stops future timed reminders on that browser. This is a self-report, not a verified appointment event. A visitor simply opening `/consult/` or loading/clicking the embedded calendar is **not** marked booked. The existing private `Appointments Booked Directly` sheet tracks appointment records independently, but its email/event ID is not linked to this browser's anonymous popup state.

Automatic suppression for every fully booked visitor still requires a first-party backend confirmation bridge: the server must match a completed Google Calendar booking to a securely bound visitor/lead identifier and return booking status to the site. Do not infer completion from iframe load, booking-page visit, or an unverified `postMessage`. Keep calendar credentials and lead email data server-side. The investor paths `/invest/` and `/calculator/` are excluded from this Living in Raleigh timed popup.

Test behavior on the TEST branch with a clean browser context. Use a local clock to confirm the 10-second, two-minute, and 30-minute delays; send a chat message and verify no popup while chat is open; submit a test form and verify one booking-screen follow-up; click the self-report button and verify suppression after navigation/reload. No real appointment is needed for these UI tests.
